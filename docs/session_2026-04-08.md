## 1. Critical Bug Fix: Data Leakage in `app/core/strategic_splitter.py`

**Problem**: `StrategicSplitter.split()` iterated per-class, so images with multiple class labels were processed once per class and could end up in different splits. **102 images were duplicated across train/val/test**, inflating metrics.

**Fix**: Introduced an `assigned` set. After placing the target class (class 4 — mining), all remaining unique stems are collected, deduplicated against `assigned`, shuffled, and split once.

```python
assigned = set(splits["train"] + splits["val"] + splits["test"])
remaining = []
for class_id, stems in images_by_class.items():
    if class_id == target:
        continue
    for stem in stems:
        if stem not in assigned:
            remaining.append(stem)
            assigned.add(stem)
random.shuffle(remaining)
# split remaining into test/val/train
```

**Verified**: Mock test with multi-class images confirmed 0 duplicates across splits.

**File**: `app/utils/logger.py`

## 8. New: Dataset Validator (`app/core/dataset_validator.py`)

`DatasetValidator` class with validation checks:

1. **Data leakage**: Compares image stems AND MD5 content hashes across train/val/test
2. **Split proportions**: Verifies ~70/15/15 ratio
3. **Target class presence**: Confirms class 4 (mining) exists in all splits
4. **Augmentation isolation**: Ensures `aug_*` images only exist in train
5. **Label integrity**: Checks image<->label pairing, no decimal class IDs
6. **Class distribution**: Logs per-class object counts per split

Entry point: `scripts/run_validation.py` (exit code 0 = pass, 1 = fail).

---

## 9. New: Overnight Script (`scripts/run_overnight.py`)

Master script for unattended execution in tmux:

```
Stage 1: DataPipelineFacade — data prep (unify, split, augment, clean, balance)
Stage 2: DatasetValidator — abort if leakage detected
Stage 3: ConservativeTrainer — 150 epochs, patience 20, checkpoints every 10
Stage 4: Log recall gate status (warn if < 0.81)
Stage 5: HyperparameterSearcher — 15 configs x 50 epochs (ALWAYS runs)
```

Features:
- `--dry-run` flag: verifies CUDA, GPU memory, all 15 configs fit, dataset exists
- Each stage wrapped in try/except (validation failure aborts, training failure doesn't prevent search)
- Incremental saving: `partial_results.csv` after every search config

Estimated time: ~7 hours max on A40.

## Deployment on ml-server03

```bash
# GPU 2 is free (GPUs 0, 1, 3 are in use)
export CUDA_VISIBLE_DEVICES=2

# Setup
cd ~/FLIR_GPF2
git pull
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt  # ~768 MB for torch+cu124

# Verify
python -m scripts.run_overnight --dry-run

# Run overnight in tmux
tmux new -s flir
python -m scripts.run_overnight 2>&1 | tee overnight.log
# Ctrl+B, D to detach

# Next morning
tmux attach -t flir
cat hyperparameter_search_*/partial_results.csv
```

**Important**: Run scripts as modules (`python -m scripts.run_overnight`) not as files (`python scripts/run_overnight.py`), since there's no `sys.path` manipulation — the module invocation ensures `app` is importable from the project root.
